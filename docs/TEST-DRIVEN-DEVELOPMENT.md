# 测试策略与集成测试脚本

> 原则依据见 [ARCHITECTURE.md](./ARCHITECTURE.md) 设计原则 9（TDD）。本文档定义测试策略与**自然语言脚本形式的集成测试**：开发收尾阶段由开发（agent）运行系统，逐场景走查并核对实际输出，确认全流程端到端跑通。

## 1. 测试策略

### 1.1 单元测试（节点级）

- **颗粒度**：以**流程节点**为最小被测单元，验证每一个节点能否跑通；不做整流程级别的测试（那是集成测试的职责）。
- **被测对象**：
  - 图节点：`interview_agent` / `unit_review_agent` / `transcribe_agent` / `document_review_agent` / `polish_agent` / `fidelity_evaluation_agent`、确定性渲染器
  - 引擎机制：API 方法分发、中断（interrupt）与输入暂存（pending_queue）、checkpoint 恢复、单会话串行（4005）
- **要求**：意义明确——断言具体行为与状态变化（输入 → 输出 → 状态），**禁止冒烟测试**（仅「无异常即通过」不算测试）。
- **框架**：pytest（占位，实现时定）。测试先于实现编写，与功能同批交付。

### 1.2 集成测试（自然语言脚本）

- **形态**：§2 的场景脚本，按自然语言步骤实际操作并核对「预期结果」，不是可执行代码。
- **执行时机**：开发收尾阶段，由开发（agent）完成。
- **通过标准**：每一步的实际输出与「预期结果」一致；任一场景未通过即整体未通过，修复后重跑全部场景。
- **执行载体**：以 `yespm-cli`（CLI，高级用法）为主；同场景亦可经 stdio（`yespm-server`）/ WebSocket（`yespm-ws`）任一端复跑，覆盖各传输路径。

## 2. 集成测试脚本

### 前置条件

1. Conda 环境 `yespm` 已就绪，`pip install -r requirements.txt` 完成，`.env` 已配置有效 LLM API Key。
2. 使用全新临时工作目录启动（避免历史 checkpoint 干扰）。
3. 需要一个真实的待访谈主题（下文以「团队任务看板」为例，可换任意主题）。

### S01 新建会话，进入首轮访谈

- 操作：启动 `yespm-cli`，输入一句话产品简述：「做一个团队任务看板，支持任务状态流转」。
- 预期：出现带当前单元上下文的提示符（如 `PRD [1 产品概述]>`）；agent 围绕首个访谈单元提问；回复后进入下一单元或继续追问；全程无异常退出。

### S02 逐单元访谈，验证转录与上下文隔离

- 操作：按模板逐单元如实作答（含必要追问）；每完成若干单元后用 `/view` 查看取值树。
- 预期：已答字段在取值树中有值、未答字段为空；单元切换后新提问基于取值树与模板描述，不引用上一单元的对话原文（上下文隔离）。

### S03 `/skip` 跳过当前单元

- 操作：在某个单元提问后输入 `/skip`。
- 预期：跳过成熟度评审、强制转录（缺失处标「待补充」）、写入取值树并**继续下一单元**，整个流程未结束。（语义见 [api/PROTOCOL.md](./api/PROTOCOL.md) §4.2 `command/skip`）

### S04 `/finish` 进入全文档审核

- 操作：访谈阶段任意时刻输入 `/finish`。
- 预期：进入全文档审核阶段并展示结果：通过则进入润色阶段；不通过则展示审核结论——自然语言描述经 `session/message` 流式推送，结构化缺口清单在 `gaps/changed` 信号后经 `query/gaps` 拉取——并回到访谈。（语义见 [api/PROTOCOL.md](./api/PROTOCOL.md) §4.2 `command/finish`）

### S05 审核回灌：对缺口重新访谈

- 操作：承接 S04 不通过的情形，按提示对 gap 所在单元重新作答。
- 预期：仅 gap 相关单元被重访（按字段有效 tier 归并，规则见 [backend/ARCHITECTURE.md](./backend/ARCHITECTURE.md) 寻址与 gap 归并一节），无关单元不再提问；转录为修订式——既有仍有效的内容保留，仅修改过时、补充缺失部分（修订式转录约束见 [backend/ARCHITECTURE.md](./backend/ARCHITECTURE.md) §2.1）。

### S06 润色：低风险转换自动应用

- 操作：进入润色阶段后，观察基线文档与 A/C 类（表格化 / 结构化）转换。
- 预期：低风险提案自动执行、无确认提示；有对应转换记录（`conversions/changed` 信号后 `query/conversions` 拉取）；未被提案覆盖的区域与确定性基线一致。

### S07 润色：高风险转换逐条确认

- 操作：出现 B/D 类（图表化 / 删减）提案时，先拒绝一条，再应用一条。
- 预期：高风险提案逐条列出（位置 / 原形态 / 目标形态 / 风险 / 理由）；被拒绝的未生效，被应用的已生效；转换日志可复核。

### S08 最终产出

- 操作：润色完成后查看最终文档。
- 预期：收到最终 Markdown（`prd/changed` 信号后经 `query/prd` 拉取）；`field_type: table` / `enum` 及 `preserve: true` 的字段未被转换；转换日志（及如有「审核未决清单」）附于文末，可经 `query/conversions` 复核；会话进入 `finished` 但仍可查询。

### S09 断点续聊：退出后恢复会话

- 操作：访谈中途 `/quit` 退出；重新启动 `yespm-cli` 并用 `/resume <id>` 恢复；继续访谈几轮后再退出、再次恢复。
- 预期：恢复后取值树、当前单元、已完成单元完整；若退出前处于等待输入，恢复后补发输入请求；可无缝继续访谈。

### S10 错误路径

- 操作：依次执行——`/resume` 一个不存在的会话 id；在会话已 `finished` 时输入普通文本；在 finished 后执行 `/skip`。
- 预期：分别返回 4001（会话不存在）、4102（当前状态不接受输入）、4103（操作当前不可用）；错误信息可读，会话进程不崩溃。

### S11 `/undo` 回退

- 操作：某单元转录完成后立即 `/undo`，随后 `/view` 核对。
- 预期：最近一次转录被回退，取值树恢复为转录前状态；再次 `/undo`（无记录时）得到 4103。

### S12 `/quit` 干净退出

- 操作：任意阶段输入 `/quit`。
- 预期：保存 checkpoint 后进程退出；重启后 `/resume` 可恢复至退出前状态。
