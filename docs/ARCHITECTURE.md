# YesPM 架构设计文档

## 整体架构

采用 LangGraph 工作流引擎，将 PRD 撰写过程建模为有向图，通过 4 个核心节点协同完成文档生成。

```
┌─────────────────────────────────────────────────────────┐
│                       User Input                         │
└────────────────────────┬────────────────────────────────┘
                         │
                         ▼
              ┌─────────────────────┐
              │ ① define_product    │   LLM + 交互式对话
              │  产品定义澄清        │  明确：目标、用户、场景、功能边界
              └─────────┬───────────┘
                        │
                        ▼
              ┌─────────────────────┐
              │ ② draft_prd         │   LLM + PRD 模板
              │  按模板撰写 PRD      │  结构化输出：背景、功能、非功能需求
              └─────────┬───────────┘
                        │
                        ▼
              ┌─────────────────────┐
              │ ③ review_prd        │   LLM + 质量标准
              │  质量审核            │  检查：完整性、一致性、可行性
              └─────────┬───────────┘
                        │
                   ┌────┴────┐
                   │ 达标？    │
                   └────┬────┘
              ┌─ 否 ──┘  └── 是 ──┐
              ▼                    ▼
    ┌──────────────┐    ┌─────────────────────┐
    │ 返回节点②     │    │ ④ finalize_prd       │
    │ 根据审核意见   │    │ 输出最终 PRD 文档     │
    │ 修改PRD       │    └──────────┬──────────┘
    └──────────────┘               │
                                   ▼
                         ┌─────────────────────┐
                         │   输出 Markdown/PDF   │
                         └─────────────────────┘
```

## 核心组件

### 1. State 定义 (`prd_state.py`)

工作流的共享状态，在各节点间传递：

| 字段 | 类型 | 说明 |
|------|------|------|
| `messages` | `list` | 对话历史 |
| `product_definition` | `dict` | 产品定义（目标用户、核心功能等） |
| `prd_draft` | `str` | PRD 草稿（Markdown） |
| `review_result` | `dict` | 审核结果（评分、意见） |
| `review_passed` | `bool` | 审核是否通过 |
| `final_prd` | `str` | 最终 PRD 文档 |
| `iteration_count` | `int` | 修改迭代次数 |

### 2. 节点说明

#### ① define_product - 产品定义节点

- **输入**: 用户初步描述
- **处理**: 通过 LLM 引导式提问，逐步明确：
  - 产品名称与定位
  - 目标用户画像
  - 核心使用场景
  - 功能优先级（P0/P1/P2）
  - 非功能性约束
- **输出**: 结构化的产品定义字典
- **LLM Prompt**: `prompts/define.txt`

#### ② draft_prd - PRD 撰写节点

- **输入**: 产品定义 + PRD 模板
- **处理**: 按模板章节逐一填写，生成结构化 Markdown
- **输出**: PRD 草稿
- **LLM Prompt**: `prompts/draft.txt`
- **模板定义**: `docs/PRD_TEMPLATE.md`

#### ③ review_prd - 审核节点

- **输入**: PRD 草稿
- **处理**: 从完整性、一致性、可行性三个维度审核
  - 完整性：各章节是否齐全，关键信息是否有遗漏
  - 一致性：前后描述是否矛盾，功能与场景是否匹配
  - 可行性：技术方案是否合理，资源评估是否可行
- **输出**: 审核评分 + 修改建议列表
- **LLM Prompt**: `prompts/review.txt`

#### ④ finalize_prd - 终稿节点

- **输入**: 通过审核的 PRD 草稿
- **处理**: 格式化排版，输出最终文档
- **输出**: 最终 PRD（Markdown 格式，可导出 PDF）

### 3. 路由逻辑

- `define_product` → `draft_prd`: 产品定义完成后直接进入撰写
- `draft_prd` → `review_prd`: 撰写完成后进入审核
- `review_prd` → `draft_prd` / `finalize_prd`: 审核未通过则返回修改，通过则进入终稿
- 最大迭代次数限制（如 3 次），防止死循环

## 扩展性

- **节点扩展**: 可在流程中插入新节点（如竞品分析、技术方案评估）
- **模板切换**: 支持加载不同的 PRD 模板适配不同业务场景
- **模型切换**: 通过环境变量切换 OpenAI / Azure / 本地模型
- **人工审核**: 可在审核节点插入 human-in-the-loop 断点
